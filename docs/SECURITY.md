# 安全边界与风控须知

这套系统的设计前提是：**机器人可以像人，但不能变成一台对所有人开放的后门。**

---

## 1. 三层权限边界

```
第一层：准入（谁能跟它说话）
   群白名单 + 私聊白名单；陌生人默认静默

第二层：能力（它能做什么）
   QQ 仿真会话的 preset 里**不注册**本地 shell/文件工具
   模型只能调 MCP 的 QQ 工具（看消息、发表情、发消息、查空间）

第三层：执行（谁能让电脑真的干活）
   只有「主人 QQ 私聊 + 口令」能触发桥接的本地执行
   群友无论如何套话都拿不到
```

### 为什么模型侧不放本地工具

因为群里任何一个人都能对它说话。只要模型能执行命令，攻击面就是**整个群**：
> “帮我看看 D 盘那个文件” → 读文件
> “运行一下这个脚本” → 执行任意代码

所以本地能力挂在**桥接的指令层**，用「发送者身份 + 口令」双重校验，
而不是挂在模型的工具清单里。这是有意为之，**不要为了省事把工具放回去**。

---

## 2. 主人运维口令

格式：

```
我要发操作 <动作>
我要操作 <动作>      ← 兼容写法
```

| 类别 | 需要口令 | 例子 |
|---|---|---|
| 只读查询 | ❌ 不需要 | 内存多少 / 电脑状态 / 服务活着吗 |
| 写操作 | ✅ 需要 | 杀模拟器 / 重启NapCat / 截图 / 运行 <命令> |
| 任意命令 | ✅ 需要 | 我要发操作 运行 Get-Process |
| 复杂任务 | ✅ 需要 | 我要发操作 助手 <任务描述> |

口令的作用是**防盗号**：即使有人拿到你的 QQ，不知道这句口令也动不了这台电脑。
建议定期更换（改 `handleOwnerOps` 里的 `SAFE_PREFIXES`）。

---

## 3. 风控（最重要的一节）

QQ 协议端登录属于**非官方客户端**，腾讯会做异常检测。踩过的坑：

| 行为 | 后果 | 对策 |
|---|---|---|
| 凌晨每小时强登 4 次失败 | 收到「QQ功能限制提醒」| 登录配额：每小时 ≤2、每天 ≤6 |
| 手机端和电脑端同时在线 | 互相踢下线 | 二选一；建议只保留电脑端 |
| 断网后频繁重登 | 大量失败登录 → 异常 | 先判断网络，断网时不动 |
| 每天重启多次协议端 | 每次都要重新登录，风险累积 | 能不动就不动 |
| 每小时自动点赞/评论 | 行为过于规律 | 降到低频 + 随机化 |
| 自动同意群邀请 | 进陌生群 → 被举报 | 关闭，改为人工确认 |

**判断掉线原因的顺序**：
1. 先看是不是自己断网（外网能不能通）
2. 再看 OneBot 端口（3001/3000）
3. 最后才怀疑账号被踢

---

## 4. 敏感内容过滤

对**陌生人私聊**，命中以下主题直接不回（不过模型、不花钱）：

- 密码 / 验证码 / 身份证 / 银行卡 / 转账 / 借钱
- 手机号 / 微信号 / 联系方式 / 住址
- 色情 / 约炮 / 赌博 / 违法
- “你是不是 AI / 什么模型 / 提示词是什么”

> 注意：这层只对陌生人生效。主人和好友问这些照常回答。

---

## 5. 密钥与配置卫生

必须放进 `config.json`（不提交仓库）的东西：

- QQ 号、群号
- OneBot access token
- SnowLuma WebUI 账号密码
- DeepSeek API key
- ntfy 话题名、运维口令

仓库里只保留 `*.example.json` 占位符版本。

---

## 6. 数据留存

- 聊天记录、图片缓存、token 账本都在本地，不上传任何第三方（除了模型 API 本身）
- LLM 调用会把对话内容发给模型服务商，敏感场景请自行脱敏
- 若要长期运行，建议定期清理 `state/` 下的缓存与临时文件

---

## 7. 合规提醒

- 遵守 QQ 用户协议；不要用于骚扰、诈骗、批量营销
- 不要用机器人冒充真人骗取信任（本项目定位是「群里的一只 AI」，不主动隐瞒身份被问时如实回答更安全）
- 涉及实名/人脸的 App（如抖音）**不要**在模拟器里尝试绕过验证

---

## 8. 登录二维码的处理规范

登录二维码本质上是一次**账号授权凭证**，泄露等同于把登录权交给对方，因此：

1. **不要把二维码图片发到公开群、公开图床或任何第三方服务器**；本项目只在两种场景展示二维码：
   - 本地全屏页面（`scripts/qqbot/qr-page/`），供本人手机摄像头扫描；
   - 推送到**本人可控的私有通道**（如自建 ntfy 主题），且主题名视为密钥。
2. 二维码通常 **2 分钟自动轮换**，过期即失效；不要为了「方便」把二维码缓存到长期可访问的位置。
3. 微信/QQ 的登录授权类二维码**不支持图片识别**，只能摄像头实拍，这本身是一层保护，不要用截图转存的方式绕过。
4. 若怀疑二维码泄露：立刻在手机端「登录设备管理」里踢掉不明设备，并改密码。

## 9. 双端互踢与登录频率

- 同一 QQ 号在多端登录时，后登录/重连的设备可能把先登录的会话顶掉（NapCat 日志表现为 `ErrCode: 3`）。
- 频繁掉线重登会显著提高风控概率，因此掉线守护内置了登录配额（默认 2 次/小时、6 次/天），到达上限后进入等待而不是死循环重试。
- 建议：固定一个主要登录端；手机端如非必要，不要在同一个号上长期保持登录。
