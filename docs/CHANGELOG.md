# 更新日志

记录本工程的实测变更与踩坑修复。日期为本地时间。

## 2026-10-23

### 修复
- **模式调度器跨午夜误触发**：旧逻辑在新的一天 00:00 就判定「睡眠已结束」并切完整模式，占用了当天的 `lastWakeDay`，导致 07:30 真正该切完整模式时被跳过（早安因此没发）。
  新逻辑：只有当前时间 **≥ 睡眠结束时间（默认 07:30）** 才允许切完整模式，并保留「每天只切一次」的状态保护。
- **`mode.ps1 full` 拉不全服务**：脚本里 `空间巡游` 用到了未定义变量 `$QZONE_DIR`，启动时抛错但不影响其它项，导致该服务静默缺失。
  新逻辑：变量修正为 `$D.qzone`，并在启动后 **6 秒逐个核实 + 失败自动重试一次**，最后打印逐项结果。
- **早安/晚安守护在精简模式下丢失**：00:30 切精简会把问候守护一起停掉，07:35 自然没人发早安。
  现在由 07:30 的完整模式切换负责重新拉起，已随上面两项一起验证。

### 新增
- `scripts/qqbot/qr-page/`：**二维码实时页面**。NapCat 每 2 分钟自动刷新登录二维码，`sync.mjs` 每 2 秒把缓存里的最新二维码同步到网页目录，`index.html` 用 3 秒轮询刷新显示。
  掉线时把页面全屏打开，手机直接对着屏幕扫，**不用等二维码重新生成**。
- `scripts/android-bot/lib.mjs` 增加 `ensureEmulator()`：模拟器没在线时自动拉起 LDPlayer 并等待就绪（最多 150 秒），避免 15:00 娱乐任务因为模拟器没开而静默失败。
- `scripts/qqbot/mode.ps1`：一键在「精简 / 完整」模式间切换（本次一并开源）。

### 实测结论（登录相关，重要）
- **QQ 拒绝相册扫码登录授权**：扫描登录二维码时如果走「相册选图」，QQ 会直接提示
  `为了保证你的账号安全，本次请求不支持图片识别或长按扫描二维码授权，请通过摄像头扫一扫重新授权登录。`
  → 也就是说「把二维码图片喂给手机 QQ 相册」这条自动化路线不可行，登录授权类二维码**只认摄像头实拍**。
- **安卓模拟器无法提供二维码画面**：LDPlayer 14 与 LDPlayer 9 的设置里都没有「相机 / 摄像头」选项，
  无法把宿主机的 OBS 虚拟摄像头（DirectShow 设备）映射进 Android；模拟器内 QQ 扫一扫只有黑屏。
  → 「模拟器自动扫码登录」方案走不通，最终采用「掉线 → 自动弹二维码页面 → 人工扫一下」的方案。
- **掉线根因记录**：NapCat 日志出现 `[Login] Login Error,ErrType: 1 ErrCode: 3` 表示登录态被服务端失效（常见于同一账号在别的设备重新登录），
  此时会自动重新生成二维码，属于**服务端踢线**而不是断网或进程崩溃。

## 2026-10-21

### 修复
- QQ 空间点赞 `tid 不能为空`：SnowLuma 返回的字段名与预期不一致，改为按 `key -> tid` 映射，并清理 `visit-state.json` 已读缓存。
- 主人运维口令在模型侧被拒：改为在桥接层本地拦截（`SAFE_PREFIXES` + 只读白名单），不依赖模型执行本地命令。
- `uiautomator dump` 报 `could not get idle state`：执行前先删旧 xml 并关闭动画，失败重试。
- 状态播报昵称乱码：调用 PowerShell 时显式设置 UTF-8 控制台编码。
- 桥接端口探活误报：改用 TCP 端口探测（3100 / 5099）而不是需要鉴权的 HTTP 接口。
